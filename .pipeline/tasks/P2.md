# P2: Lane OpenCode làm việc nhầm repo khi server đã gắn với repo khác

## Bối cảnh

Sự cố thật, xảy ra khi chạy task P1 của chính repo này:

`oc-run.ps1` bật TUI mặc định → gọi `oc-tui.ps1` → attach vào server opencode ở
`http://127.0.0.1:4096`. Server đó **đã được khởi động từ trước trong thư mục
`F:\Project\jellyfin`**, nên mọi phiên trên nó lấy jellyfin làm gốc dự án. Dù lệnh được chạy với
thư mục hiện tại là `F:\Project\claude-pipeline`, coder vẫn đọc và sửa file trong jellyfin:

```
> build · deepseek-v4.1-flash
↳ Read F:/Project/jellyfin/docs/AI_BUSINESS_RULES.md
$ git log --oneline -5
c199ac9 chore(pipeline): mark CX11 done      <- commit cua jellyfin
```

Kết quả: bản vá đi vào nhầm repo, còn runner báo `no-change` vì `git status` ở repo đúng không
có gì đổi. Lần đó may vì repo kia tình cờ có bản copy giống hệt; lần sau là sửa bậy vào một dự
án không liên quan mà không ai biết.

**Server opencode có API trả lời đúng câu hỏi cần hỏi** (đã kiểm bằng curl trên máy này):

```
GET http://127.0.0.1:4096/project/current
{"id":"01fe1676...","worktree":"F:\\Project\\jellyfin","vcs":"git","time":{...}}

GET http://127.0.0.1:4096/session
[{"id":"ses_f577bdf5affe0dJdM7keUHGWIg","directory":"F:\\Project\\jellyfin", ...}, ...]
```

Nên vá được chắc chắn, không phải đoán.

## Việc cần làm

### 1. `bin/oc-tui.ps1`: mỗi repo một server riêng

Hiện script nhận `-Url` mặc định `http://127.0.0.1:4096`, thấy server sống là dùng luôn. Đổi
thành: **tìm hoặc tạo server đúng của repo hiện tại.**

- Quét cổng từ `4096` tới `4105`. Với mỗi cổng, gọi `GET <url>/project/current` (timeout ngắn,
  2-3 giây, bọc try/catch):
  - Không có server → nhớ đây là cổng trống đầu tiên, đi tiếp.
  - Có server và `worktree` **khớp** `$repo` → dùng cổng này, dừng quét.
  - Có server nhưng `worktree` khác → bỏ qua, đi tiếp.
- So sánh `worktree` với `$repo` phải chuẩn hoá: đổi `/` thành `\`, bỏ dấu `\` cuối, so sánh
  **không phân biệt hoa thường** (`-ieq`). Git trả `F:/Project/x`, server trả `F:\Project\x`.
- Không thấy server nào của repo này → khởi động server mới ở **cổng trống đầu tiên** đã ghi
  nhận, với `-WorkingDirectory $repo` như hiện nay, chờ tối đa 30 giây, rồi **kiểm lại**
  `/project/current` đúng `$repo` mới đi tiếp. Nếu sau khi lên mà vẫn không khớp → in lỗi rõ và
  `exit 4`.
- Hết cổng 4096-4105 mà không chỗ nào dùng được → in lỗi rõ, `exit 4`.
- Nếu người gọi truyền `-Url` tường minh thì **tôn trọng** lựa chọn đó, nhưng vẫn phải kiểm
  `worktree`; khác repo thì từ chối với `exit 4` chứ không âm thầm dùng.
- In thêm **một dòng `URL=<url đang dùng>`** ngay trước dòng `SESSION=<id>` để bên gọi biết
  server nào.

Phần còn lại giữ nguyên: đóng cửa sổ cũ, bản đồ phiên Claude → phiên opencode, mở cửa sổ CMD
mới, ghi `tui.json`.

### 2. `bin/oc-run.ps1`: dùng URL do oc-tui trả về

Hiện oc-run đặt `$Attach = "http://127.0.0.1:4096"` rồi chỉ đọc dòng `SESSION=` từ output của
oc-tui. Sửa: đọc **cả** dòng `URL=` và gán vào `$Attach`. Nếu không có dòng `URL=` (bản oc-tui
cũ) thì giữ nguyên giá trị hiện tại.

### 3. `bin/oc-run.ps1`: chốt chặn cuối trước khi giao việc

Đây là lưới an toàn, phải có kể cả khi phần trên đã đúng. Ngay **trước** khi gọi `opencode run`,
nếu có `$Attach` (tức đang attach chứ không phải `-NoTui`):

- Gọi `GET $Attach/session`, tìm phần tử có `id` bằng `$Session`, lấy trường `directory`.
  (Nếu không tìm thấy phiên trong danh sách thì thử `GET $Attach/session/$Session`.)
- Chuẩn hoá rồi so với `$repo`. **Khác nhau → không chạy opencode**, in:

  ```
  BLOCKED: phien opencode dang o '<directory>' nhung repo hien tai la '<repo>'.
  Coder se sua nham du an. Dung -NoTui, hoac dong server dang chiem cong roi chay lai.
  ```

  rồi `exit 9` (mã mới, chưa dùng; các mã đang dùng: 2, 3, 5, 6, 7, 8, 124).
- Không hỏi được server (mạng/timeout) → **không chặn**, chỉ in một dòng cảnh báo rồi chạy tiếp;
  chốt chặn không được biến thành điểm chết mới.

### 4. Tài liệu

- `skill/SKILL.md`, phần nói về TUI của lane OpenCode: thêm rằng mỗi repo có server riêng
  (cổng 4096-4105), và nếu thấy `BLOCKED: phien opencode dang o ...` thì nghĩa là server đang
  bị repo khác chiếm — dùng `-NoTui` hoặc đóng server đó.
- `README.md`: một dòng trong phần lưu ý rằng chạy nhiều repo song song thì mỗi repo chiếm một
  cổng trong dải đó.

## Luật bắt buộc của repo

- Không commit, không `git add`, không `git stash`, không `git reset`, không `git checkout`.
- Chỉ giết tiến trình do chính bạn sinh ra và biết PID. **Không được giết server opencode ở cổng
  4096** — nó đang phục vụ repo jellyfin của người dùng.
- Repo này không có test suite; đừng tạo ra một cái.

## Quy ước phải theo

- Windows PowerShell 5.1: không `&&`, `||`, `? :`, `??`, `?.`.
- Chú thích ASCII không dấu, giống phong cách sẵn có.
- Không refactor phần khác của hai script; không đổi các mã thoát đang dùng.

## Tiêu chí chấp nhận

Ba bài đầu **không tốn lượt model nào** — chỉ gọi API và kiểm mã thoát.

- [ ] Parse sạch PS 5.1 cho `bin/oc-tui.ps1` và `bin/oc-run.ps1` → 0 lỗi.
- [ ] **Chốt chặn hoạt động:** trong một repo git tạm ở `$env:TEMP` (`git init`, một commit),
      chạy `oc-run.ps1 -TaskFile <brief nho> -Attach http://127.0.0.1:4096 -Session <id phien
      cua jellyfin lay tu GET /session>` → phải in `BLOCKED: phien opencode dang o ...` và
      **exit 9**, và **không** có tiến trình `opencode run` nào được sinh ra. Dán output.
- [ ] **oc-tui chọn đúng server:** trong repo tạm đó chạy
      `powershell -File bin\oc-tui.ps1` → output phải có dòng `URL=http://127.0.0.1:<cong khac 4096>`
      và `SESSION=...`; rồi `curl <url>/project/current` phải trả `worktree` đúng repo tạm.
      Dán cả hai. Sau đó **tự đóng cửa sổ TUI và server bạn vừa tạo** (chỉ cái bạn tạo).
- [ ] **Không đụng server của jellyfin:** sau các bài trên,
      `curl http://127.0.0.1:4096/project/current` vẫn trả `worktree` = `F:\Project\jellyfin`.
      Dán output.
- [ ] **Chạy thật trong repo tạm:** giao một brief nhỏ ("tạo file `p2.txt` chứa một dòng OK")
      bằng `oc-run.ps1` **không** truyền `-NoTui` → coder phải sửa file trong **repo tạm**, exit 0,
      và `git log` mà nó nhìn thấy không được là của jellyfin. Dán khối `--- KET QUA ---` và
      nội dung file.
- [ ] `git status --porcelain` trong repo này → đúng 4 file `M` trong danh sách được phép.

## Không làm

- Không bỏ chế độ TUI, không đổi hành vi `-NoTui`.
- Không tự đóng/giết server opencode của repo khác trong lúc chạy bình thường.
- Không đổi định dạng khối `--- KET QUA ---` hay các mã thoát cũ.
