# P6: Thêm `-NoGitTrack` — cài mà không để lại vết trong git của repo đích

## Bối cảnh

Cài gói vào một repo đích sẽ thêm `.claude/agents/*`, `.claude/skills/pipeline/SKILL.md` và
cả cây `.pipeline/`. Nhiều repo **commit thư mục `.claude/`** (tooling của team được check-in),
nên sau khi cài, toàn bộ file của pipeline hiện trong `git status` và dễ bị push nhầm lên
remote chung.

Hiện người dùng phải tự xử: thêm rule vào `.gitignore` gốc (nhưng file đó cũng được commit nên
lại sinh diff), hoặc `.git/info/exclude` (chỉ local, mất khi clone lại, nằm ngoài tầm quản của
installer). `.pipeline/.gitignore` mà installer sinh ra chỉ ignore **bên trong** `.pipeline/`
(`logs/`, `tui.json`, …), không làm bản thân `.pipeline/` vô hình.

Cơ chế dùng để vá: một `.gitignore` chứa đúng một dòng `*` sẽ ignore mọi thứ trong thư mục đó
**kể cả chính nó**. Đã kiểm trên git thật, ba điều sau đều đúng:

- `git status` sạch hoàn toàn sau khi đặt file đó;
- file đã được commit từ trước **vẫn tracked** (không phá gì của team);
- **tác dụng phụ:** file *mới, chưa tracked* của team trong cùng thư mục **cũng bị giấu**.

## Việc cần làm

### 1. `install.ps1`: thêm `[switch]$NoGitTrack`

Mặc định **tắt** — không có cờ này thì hành vi phải y hệt hiện nay.

Thêm một mục mới **đặt sau mục 4 (`Du lieu nguoi dung`)**: khi `-NoGitTrack` bật, ghi một file
`.gitignore` chứa đúng một dòng `*` vào **cả ba** thư mục:

```
<target>\.pipeline\.gitignore
<target>\.claude\agents\.gitignore
<target>\.claude\skills\pipeline\.gitignore
```

Yêu cầu chi tiết:

- Ghi bằng `Set-Content -Encoding UTF8`.
- **`-NoGitTrack` thắng logic "GIU NGUYEN"** ở mục 4: `.pipeline\.gitignore` đang được coi là
  dữ liệu người dùng nên bị giữ nguyên nếu đã có; với `-NoGitTrack` thì phải ghi đè thành `*`.
- **`-NoGitTrack` cũng thắng `-Force`**: hai cờ cùng bật thì nội dung cuối vẫn là `*`.
- Idempotent: chạy lại nhiều lần không hỏng, không nhân đôi nội dung.
- In log theo đúng style sẵn có, nêu rõ lý do ghi đè, ví dụ:
  - `TAO: .claude\agents\.gitignore (NoGitTrack)`
  - `DE: .pipeline\.gitignore (NoGitTrack)`

### 2. `README.md`: một mục ngắn về `-NoGitTrack`

Đặt gần mục Cài đặt. Nói đủ ba ý, đừng bán hàng:

- **Dùng khi nào:** repo đích có commit `.claude/`, không muốn file của pipeline hiện trong
  `git status` hay bị push lên remote chung.
- **Giới hạn 1:** ba file `.gitignore` đó tự ignore chính nó nên không được commit — clone repo
  đích ở máy khác là mất, phải chạy lại `install.ps1 -NoGitTrack`.
- **Giới hạn 2 (quan trọng, đã đo):** nó giấu **cả thư mục** với git, không chỉ file của gói.
  Nếu team để agent riêng trong `.claude/agents/`, **file mới chưa tracked của họ cũng biến mất
  khỏi `git status`** và dễ bị quên commit. File đã tracked từ trước thì không sao, vẫn tracked
  bình thường.
- Nói rõ đây **không** phải hàng rào chống đồng nghiệp lỡ tay commit. Muốn vậy phải thêm rule
  vào `.gitignore` gốc của repo đích và chấp nhận diff của chính rule đó.

## File được phép sửa

- `install.ps1`
- `README.md`

## File CẤM đụng vào

- `bin/*`, `agents/*`, `skill/SKILL.md`, `templates/*` (gồm cả `templates/pipeline.gitignore` —
  bản mặc định khi không có `-NoGitTrack` giữ nguyên), `.pipeline/`.

## Luật bắt buộc của repo

- Không commit, không `git add`, không `git stash`, không `git reset`, không `git checkout`.
- Chỉ giết tiến trình do chính bạn sinh ra và biết PID, và phải kiểm `ProcessName` trước.
  **Không lọc tiến trình bằng cách khớp chuỗi số trong dòng lệnh** — hôm nay một bộ lọc kiểu
  `'*4098*'` đã giết nhầm 11 tiến trình VS Code của người dùng.
- Repo này không có test suite; đừng tạo ra một cái.

## Quy ước phải theo

- Windows PowerShell 5.1: không `&&`, `||`, `? :`, `??`, `?.`, không `-AsHashtable`.
- Chú thích ASCII không dấu, giống phong cách sẵn có.
- Không refactor phần khác của `install.ps1`.

## Tiêu chí chấp nhận

Dán output thật của từng lệnh.

- [ ] Parse sạch PS 5.1 cho `install.ps1` → 0 lỗi.
- [ ] **Bài chính:**

  ```powershell
  $t = Join-Path $env:TEMP ("pipetest-" + [guid]::NewGuid().ToString("N").Substring(0,8))
  New-Item -ItemType Directory $t | Out-Null
  git -C $t init -q
  .\install.ps1 -Target $t -NoGitTrack
  git -C $t status --short          # phai TRONG
  git -C $t check-ignore -v .pipeline/pipeline.config.json .claude/agents/codex-coder.md .claude/skills/pipeline/SKILL.md
  .\install.ps1 -Target $t -NoGitTrack   # chay lai lan 2
  git -C $t status --short          # van phai TRONG
  ```

  Cả hai lần `git status --short` phải rỗng; `check-ignore -v` phải chỉ ra đúng ba file
  `.gitignore` vừa ghi.
- [ ] **Không regression:** cài vào một repo test khác **không** có `-NoGitTrack` →
      `git status --short` hiện đủ file như trước khi sửa (`.claude/`, `.pipeline/`), và
      `.pipeline/.gitignore` có nội dung cũ (`logs/` …), không phải `*`.
- [ ] **`-NoGitTrack` thắng "GIU NGUYEN":** trong repo test đã cài **không** có cờ (tức
      `.pipeline/.gitignore` đang là bản mặc định), chạy lại **có** `-NoGitTrack` → in
      `DE: .pipeline\.gitignore (NoGitTrack)` và nội dung file đổi thành `*`.
- [ ] **`-NoGitTrack` + `-Force`** cùng lúc → nội dung ba file vẫn là `*`.
- [ ] Dọn sạch các repo test đã tạo trong `$env:TEMP` (nêu đường dẫn đã xoá).
- [ ] `git status --porcelain` trong repo này → đúng hai file `M`: `install.ps1`, `README.md`.

## Không làm

- Không đổi `templates/pipeline.gitignore`.
- Không tự ghi `.gitignore` khi **không** có `-NoGitTrack`.
- Không đụng `.git/info/exclude` của repo đích, không chạy `git` để sửa cấu hình repo đích.
