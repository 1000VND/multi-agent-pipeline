# P3: README chưa khớp thực tế sau CX8–CX10 và P1–P2

## Bối cảnh

README hiện tại viết từ lúc tách gói, còn đúng phần lớn, nhưng thiếu và sai vài chỗ đã đổi qua
các lượt CX8 (TUI Codex gốc làm mặc định), CX9 (xoá cửa sổ watcher tự chế), CX10 (chính sách
model), P1 (thiếu `test_command` thì bỏ qua test) và P2 (mỗi repo một server opencode).

Người lạ clone về sẽ vấp đúng những chỗ thiếu này, nên rà lại một lượt.

## Việc cần làm — chỉ sửa `README.md`

### 1. Tên gói sai

Dòng tiêu đề đang là `# claude-pipeline` và phần cài đặt ghi `cd claude-pipeline`. Repo tên
**`multi-agent-pipeline`**. Sửa cả hai chỗ, và dùng URL thật trong lệnh clone:
`git clone https://github.com/1000VND/multi-agent-pipeline.git`.

### 2. Thêm mục "Yêu cầu" ngay sau phần mô tả

Gói này **chỉ chạy trên Windows** — toàn bộ là PowerShell 5.1, có `taskkill /T /F`,
`Start-Process`, đường dẫn `%USERPROFILE%\.codex\sessions`. Nói thẳng điều đó, rồi liệt kê:

- Windows PowerShell 5.1 (`install.ps1` cảnh báo nếu không phải bản này)
- git
- `codex` trong PATH và **đã đăng nhập** — cần cho lane Codex
- `opencode` trong PATH — cần cho lane OpenCode
- python hoặc runtime test của dự án — tùy `test_command`

Nói thêm: `install.ps1` in sẵn báo cáo `== DIEU KIEN CHAY ==` với OK/THIEU cho từng thứ, thiếu
thì không fail mà chỉ báo lane nào không dùng được.

### 3. Thêm mục "Chạy một task" (hiện chưa có)

Người mới không biết gọi gì sau khi cài. Viết ngắn, đúng hai lệnh:

```powershell
powershell -NoProfile -File .pipeline\bin\oc-run.ps1    -TaskFile .pipeline\tasks\<id>.md
powershell -NoProfile -File .pipeline\bin\codex-run.ps1 -TaskFile .pipeline\tasks\<id>.md
```

Kèm: lượt sửa lỗi thêm `-Resume`; brief phải **tự chứa** vì coder không thấy hội thoại; chi tiết
quy trình nằm trong `SKILL.md` mà Claude đọc.

### 4. Bổ sung phần lane Codex (thiếu hẳn, đây là chỗ dễ vấp nhất)

- Mặc định runner Codex mở **TUI Codex gốc** để người dùng nhìn thấy nó làm việc; cửa sổ ở lại
  sau khi xong để đọc tiếp.
- `-Exec` hoặc `-NoTui` chạy headless, không mở cửa sổ nào.
- **Điều kiện bắt buộc của TUI:** thư mục phải nằm trong danh sách tin cậy của Codex
  (`~/.codex/config.toml`, mục `[projects.'...']` với `trust_level = "trusted"`). Thư mục lạ thì
  TUI chặn lại hỏi xác nhận và runner chỉ biết chờ tới timeout. Cách mồi: chạy một lượt
  `-NoTui` nhỏ trong repo đó trước, lượt headless tự đăng ký tin cậy.
- Log: JSONL nằm ở `.pipeline/logs/`; chế độ TUI sao chép rollout của Codex thành
  `<task>-<tag>-native.jsonl`, chế độ headless ghi `<task>-<tag>-codex.jsonl` cộng `.err` cho stderr.

### 5. `test_command` để trống thì bỏ qua test

Trong bảng `pipeline.config.json`, sửa mô tả `test_command`: để trống thì runner **không chạy
gì** và in `TESTS: khong co test_command trong .pipeline/pipeline.config.json - bo qua`. Đây là
hành vi có chủ đích, không phải lỗi.

### 6. Thêm bảng mã thoát (chưa có, rất cần khi đọc log)

Dùng đúng các mã có thật trong code, đã rà:

| Mã | Nghĩa |
|---|---|
| 0 | xong, có thay đổi file |
| 2 | không phải git repo / không thấy task file / model bị cấm |
| 3 | worktree bẩn (chỉ lượt không `-Resume`) |
| 4 | thiếu Codex CLI, hoặc không có thread đã lưu để `-Resume` |
| 5 | lượt này không sửa gì — coi như thất bại |
| 6 | `oc-tui.ps1` không trả về session id (chỉ lane OpenCode) |
| 7 | CLI hỏng cứng, không phải model từ chối task |
| 8 | có thay đổi nhưng `test_command` fail |
| 9 | phiên opencode thuộc repo khác — chặn để khỏi sửa nhầm dự án (chỉ lane OpenCode) |
| 124 | quá `timeout_sec`, runner đã giết cả cây tiến trình |

### 7. Mục "Lưu ý": bổ sung ý nghĩa của exit 9

Đang có một gạch đầu dòng về dải cổng `4096-4105`. Thêm: nếu thấy
`BLOCKED: phien opencode dang o '<duong dan>'` thì nghĩa là phiên đang thuộc repo khác — dùng
`-NoTui`, hoặc đóng server đang chiếm cổng, rồi chạy lại. Lỗi này từng làm coder sửa nhầm sang
một dự án khác nên chốt chặn cố ý chặn hẳn thay vì cảnh báo.
