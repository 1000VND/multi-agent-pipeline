# P4: Bản đồ phiên có thể hồi sinh phiên của repo khác

## Bối cảnh

P2 đã lo phần chọn **server** đúng repo, nhưng phần chọn **phiên** vẫn hở. Trong
`bin/oc-tui.ps1`:

```powershell
function Test-Session($sid) {
  try { Invoke-RestMethod -Uri "$Url/session/$sid" -TimeoutSec 6 -ErrorAction Stop | Out-Null; return $true }
  catch { return $false }
}
```

Nó chỉ hỏi "phiên này có tồn tại không", không hỏi "phiên này thuộc thư mục nào". Mà kho phiên
của opencode **dùng chung toàn máy**, không giới hạn theo project — đo được trực tiếp: hỏi
server của repo A về phiên của repo B thì vẫn trả về đầy đủ.

```
GET http://127.0.0.1:4097/session/ses_f577bdf5affe0dJdM7keUHGWIg
-> { "id": "ses_f577bdf5affe0dJdM7keUHGWIg", "directory": "F:\\Project\\jellyfin" }
```

(4097 là server của `F:\Project\claude-pipeline`, còn phiên đó thuộc `F:\Project\jellyfin`.)

Hậu quả thật, vừa xảy ra ở lượt P3: `.pipeline/tui-map.json` của repo này còn giữ một id phiên
cũ của jellyfin (rác từ lúc phát triển P2). `Test-Session` thấy "tồn tại" nên dùng lại, và cả
lượt chạy bị chốt chặn của `oc-run.ps1` dừng ở `exit 9`. Chốt chặn làm đúng việc, nhưng người
dùng mất một lượt và phải xoá file bản đồ bằng tay.

Cần chuyển từ "hỏng rồi mới chặn" sang "không chọn nhầm ngay từ đầu".

## Việc cần làm — chỉ sửa `bin/oc-tui.ps1`

Đổi `Test-Session` thành kiểm cả thư mục của phiên, không chỉ sự tồn tại:

- Gọi `GET $Url/session/$sid`, lấy trường `directory`.
- Chuẩn hoá hai vế rồi so sánh (đã có sẵn hàm `Normalize-RepoPath` trong file, dùng lại):
  `/` → `\`, bỏ `\` cuối, so sánh **không phân biệt hoa thường**.
- Trả về "dùng được" **chỉ khi** `directory` khớp `$repo`.
- Không gọi được server hoặc phiên không tồn tại → "không dùng được", giữ nguyên hành vi cũ là
  tạo phiên mới.

Ở chỗ tra bản đồ, phân biệt hai lý do trong thông báo để người đọc log hiểu chuyện gì xảy ra:

- phiên không còn trên server → giữ nguyên câu hiện tại
  (`phien cu (<id>) khong con tren server, se tao moi`);
- phiên còn nhưng thuộc repo khác → câu mới, nêu rõ thư mục, ví dụ
  `phien cu (<id>) thuoc repo '<directory>', khong dung duoc o day - se tao phien moi`.

Cả hai trường hợp đều đi tiếp bằng đường tạo phiên mới sẵn có, và ghi đè mục cũ trong bản đồ
bằng phiên mới. **Không** tự xoá file bản đồ, **không** đụng mục của khoá phiên Claude khác.

Giữ nguyên mọi thứ còn lại: quét cổng 4096-4105, khởi động server theo repo, đóng cửa sổ cũ,
`-Fresh`, `-CloseOnly`, in `URL=` rồi `SESSION=`.

## Luật bắt buộc của repo

- Không commit, không `git add`, không `git stash`, không `git reset`, không `git checkout`.
- **Không được giết server opencode ở cổng 4096** (đang phục vụ repo jellyfin của người dùng),
  và không xoá phiên nào của nó. Server/cửa sổ nào bạn tự tạo để test thì tự dọn.
- Repo này không có test suite; đừng tạo ra một cái.

## Tiêu chí chấp nhận

Không bài nào cần gọi model — chỉ gọi API và đọc output.

- [ ] Parse sạch PS 5.1 cho `bin/oc-tui.ps1` → 0 lỗi.
- [ ] **Dựng lại đúng sự cố:** trong một repo git tạm ở `$env:TEMP` (`git init`, một commit),
      tạo `.pipeline/tui-map.json` có một mục trỏ tới **phiên của repo khác** — dùng
      `ses_f577bdf5affe0dJdM7keUHGWIg` (thuộc `F:\Project\jellyfin`, đang sống trên cổng 4096),
      với khoá đúng bằng khoá phiên Claude mà script sẽ dùng (đọc `$env:CLAUDE_CODE_HOST_SESSION_ID`,
      không có thì `$env:CLAUDE_CODE_SESSION_ID`, không có nữa thì `no-claude-session`; hoặc
      đơn giản là truyền `-Key test-p4` cho script và đặt khoá đúng như vậy).
      Chạy `oc-tui.ps1 -Key test-p4` trong repo tạm đó. Kỳ vọng, dán đủ:
      1. có dòng báo phiên cũ thuộc repo khác, nêu đúng `F:\Project\jellyfin`;
      2. dòng `SESSION=` trả về **id khác** `ses_f577bdf5affe0dJdM7keUHGWIg`;
      3. `curl <URL>/session/<id moi>` cho `directory` đúng repo tạm;
      4. `.pipeline/tui-map.json` sau đó chứa id mới, không còn id của jellyfin.
- [ ] **Không phá việc dùng lại phiên:** chạy `oc-tui.ps1 -Key test-p4` lần thứ hai trong cùng
      repo tạm → phải in `DUNG LAI phien opencode cu` với **đúng id** vừa tạo ở bài trên.
- [ ] **Jellyfin không bị đụng:** `curl http://127.0.0.1:4096/project/current` vẫn trả
      `F:\Project\jellyfin`, và `curl http://127.0.0.1:4096/session/ses_f577bdf5affe0dJdM7keUHGWIg`
      vẫn trả về phiên đó (chứng minh bạn không xoá phiên của người ta).
- [ ] Dọn sạch: cửa sổ TUI và server bạn tạo cho repo tạm đã tắt; nêu PID đã đóng.
- [ ] `git status --porcelain` trong repo này → đúng một file `M bin/oc-tui.ps1`.

## Không làm

- Không xoá file bản đồ, không xoá phiên trên server — chỉ bỏ qua phiên không hợp lệ.
- Không gộp chốt chặn của `oc-run.ps1` vào đây; hai lớp phải độc lập.
- Không đổi định dạng hai dòng `URL=` và `SESSION=` (bên gọi đang parse).
